Lighter and faster, sturdier Epic and GOG finding on Windows, a choice of controller buttons, and a way to report problems.

- With the panel open, Hanami now uses well under half the CPU it did in 0.2.13 (about 3 % of one core instead of 7 % on our test machine), because only the rows you can see are drawn. A library of a thousand games costs about as much as one of forty.
- The panel opens at once with the games it found last, and looks for new ones after it's up.
- On X11 the hotkey no longer wakes Hanami 20 times a second, and Ctrl+Alt+H opens the panel in a few milliseconds instead of up to 60.
- Icons are kept at the size they're drawn, which saves memory: about 28 MB with 200 games.
- Report a problem in the tray menu opens a GitHub issue filled in with your version and system, and with what went wrong if Hanami hit a bug. Nothing is sent until you press Submit.
- Epic on Windows: games are found from the launcher's own data folder, games left behind by an uninstall are skipped, and manifests with a byte order mark are read.
- GOG on Windows: a missing game path is filled in from the game's `goggame-<id>.info`, and games start through GOG Galaxy when it is installed.
- `controller_buttons` in the settings picks the buttons you hold to open the panel. With `controller = false`, nothing controller-related runs at all.

Benchmarks for every release are in docs/benchmarks.md.

The Acrylic blur on Windows 11 is in the code but stays off until it has been checked on real machines. It is planned for 0.2.15.
